# MetaEXB 新用戶試用修改需求

日期：2026-09-05  
試用網站：https://metaexb.com/  
狀態：2026-09-05 已完成主要新手流程修改並部署香港；具體測試證據與仍保留的後續項目見 [實作與部署結果](plans/2026-09-05-new-visitor-results.md)。下列清單保留為原始需求基準，不代表所有延伸選項均已交付。

## 1. 修改目標

讓第一次到訪、想為學生建立成果展的教師，能夠先看到完整展覽、理解操作方式，再決定註冊及建立自己的展覽。

建議主流程：

首頁 → 免登入參觀示範展 → 查看作品與體驗互動 → 上傳作品建展 → 登入／註冊 → 返回原本建展流程。

優先解決「尚未體驗產品價值，就遇到登入門檻或沒有內容可看」的問題。

## 2. 試用範圍與證據限制

本次以未登入訪客身份，實際操作首頁、影片教學、上傳作品建展入口、展覽列表、虛擬展廳、現代藝術畫廊模板及加入展廳視窗。

未完成登入、上傳、儲存及發布，也未進入完整展館。因此，本文不判斷編輯器操作品質、AI 輸出品質、多人同步或手機實際效能。

以下觀察反映試用當時的頁面狀態；實作前應重新確認。示範展、短碼及 QR Code 等內容是修改建議，不代表現有功能。

## 4. 具體修改需求

### UX-01：提供免登入官方示範展

**實際觀察**

首頁有 3D 展館預覽，但本次未找到可以直接進入完整示範展的明確入口。點擊「上傳作品建展」及現代藝術畫廊的「使用此模板」均進入登入頁。

**修改要求**

- 首頁首屏增加「免登入參觀示範展」，與「上傳作品建展」並列。
- 提供一個內容完整、明確標示為官方示範的展覽，展示作品標題、說明及基本參觀互動。
- 進入展覽後，用簡短提示說明如何移動、查看作品及返回首頁。
- 參觀後提供「建立我的展覽」入口。
- 示範展只提供公開參觀能力；建立、編輯及保存仍沿用原本權限機制。
- 使用經授權或自行製作的展示素材；若支援 AI 體驗，應另行確認訪客權限、限流及不可用時的提示。

**驗收標準**

- [ ] 未登入訪客從首頁一次點擊即可進入示範展入口，無需先註冊。
- [ ] 可成功載入展館、查看至少一件作品詳情並離開展館。
- [ ] 初次參觀者能找到操作提示。
- [ ] 手機可參觀；3D 不可用時有清楚提示或可用的替代觀看入口。
- [ ] 公開參觀不會取得編輯權限。

### UX-02：改善沒有公開展覽時的頁面

**實際觀察**

展覽列表顯示「目前沒有進行中的展覽」，首頁的展覽紀念區也顯示暫無公開紀念卡。

**修改要求**

- 展覽列表為空時，展示官方示範展卡片及「立即參觀示範展」。
- 將官方示範與用戶發布內容清楚區分，不以示範內容冒充真實活動。
- 首頁沒有公開紀念卡時，縮減該區塊或改放示範展入口，避免持續呈現沒有內容的主要區域。
- 分別處理載入中、載入失敗及資料為空；API 失敗不得直接顯示為沒有展覽。

**驗收標準**

- [ ] 沒有公開展覽時，訪客仍可由頁面進入示範展。
- [ ] 有公開展覽時，正常展示真實內容。
- [ ] 載入失敗時提供錯誤提示及重試入口。
- [ ] 示範內容不計為真實用戶展覽或參觀紀念。

### UX-03：讓教學入口提供真正可用的教學

**實際觀察**

點擊首頁「影片教學」後，視窗顯示播放圖案與介紹文字；本次未看到影片播放控制或實際教學步驟。這是介面觀察，尚未確認底層是否配置影片來源。

**修改要求**

- 有影片時，提供可播放的短教學，涵蓋上傳、排展、預覽及分享。
- 影片尚未完成時，將入口改名為「快速上手」，提供有畫面及步驟的圖文教學。
- 不保留看似可以播放、卻只作裝飾的播放圖案。
- 教學清楚說明需要登入的步驟，以及手機參觀與桌面編輯的能力差異。

**驗收標準**

- [ ] 入口名稱與實際內容一致。
- [ ] 用戶能透過教學理解完成第一個展覽的主要步驟。
- [ ] 影片方案具備播放控制、字幕及載入失敗提示；圖文方案可完整閱讀。
- [ ] 可使用鍵盤開啟及關閉視窗，關閉後焦點返回原入口。

### UX-04：統一模板可用狀態

**實際觀察**

虛擬展廳同時顯示「模板準備中，敬請期待」與六張附有「使用此模板」按鈕的模板卡片。實際點擊現代藝術畫廊後跳到登入頁，未驗證登入後是否套用成功。

**修改要求**

- 逐一確認模板是否具備可套用的場景資料。
- 可用模板顯示「預覽模板」及「使用此模板」。
- 尚未完成的模板標示「即將推出」，不提供會造成可用錯覺的使用按鈕。
- 只有部分模板未完成時，移除整個模板區「準備中」的籠統說明。
- 預覽應反映實際模板內容。
- 登入後保留所選模板，避免回到沒有選擇資訊的建立頁。

**驗收標準**

- [ ] 每張卡片的標示與實際能力一致。
- [ ] 可用模板能預覽，並在登入後正確帶入建立流程。
- [ ] 未完成模板不會誤導用戶進入使用流程。

### UX-05：改善登入前後的流程銜接

**實際觀察**

「上傳作品建展」直接進入標題為「歡迎回來」的登入頁。對首次使用者而言，建立展覽的上下文不明顯。本次未驗證登入後是否返回原頁，不能視為已發現返回流程失效。

**修改要求**

- 保留直接登入能力，同時清楚提示「登入或註冊後，繼續建立你的展覽」。
- 在需要登入的建展入口附近，簡短說明登入要求。
- 提供「先參觀示範展」替代入口。
- 驗證登入與註冊完成後，均能返回原建展路徑並保留模板選擇。
- 返回地址只接受允許的站內路徑，沿用既有驗證機制。

**驗收標準**

- [ ] 從建展入口進入登入頁時，可理解登入原因及下一步。
- [ ] 登入、註冊後返回正確流程。
- [ ] 取消登入後仍能返回公開頁面及示範展。
- [ ] 不產生任意外部網址重新導向。

### UX-06：簡化加入展廳

**實際觀察**

「加入展廳」視窗要求輸入展覽 ID，提示範例是一串 UUID。對課堂分享而言，不適合口頭傳遞或手動輸入。

**首輪修改要求**

- 輸入欄改為「展覽連結或 ID」。
- 支援貼上本站既有格式的展覽分享連結，並保留原 ID 相容性。
- 對照既有公開展覽、分享 token 等路由，分別解析及驗證；不可把不同識別方式混為一談。
- 提供格式錯誤、不存在、已失效及無權限的適當提示，避免洩漏私人展覽資訊。
- 說明「請向老師或主辦人索取展覽連結」。

**後續選項**

- 由展覽分享介面產生 QR Code。
- 評估短碼加入；須同時設計有效期、防枚舉與訪問控制，不能單靠縮短 ID 實作。

**驗收標準**

- [ ] 有效的本站展覽連結與原有 ID 都能進入正確流程。
- [ ] 外部網址及不支援格式不會被任意開啟。
- [ ] 私人或受限展覽保留既有權限要求。
- [ ] 錯誤提示提供可理解的下一步，不只回傳技術錯誤。

### UX-07：改善深色介面易讀性

**實際觀察**

本次桌面畫面採黑金配色，部分灰色說明與導覽細字視覺上偏暗。尚未量測對比，因此不直接判定違反無障礙標準。

**修改要求**

- 量測正文、次要文字、導覽及按鈕標籤的對比。
- 一般文字以至少 4.5:1、大型文字以至少 3:1 為驗收目標。
- 調整共用文字色彩及必要字級，保留既有視覺風格。
- 同步檢查深淺色模式、鍵盤焦點及手機寬度下的可讀性。

**驗收標準**

- [ ] 主要受影響文字符合上述對比目標。
- [ ] 不以降低文字透明度作為唯一層級區分方式。
- [ ] 常見手機寬度下無文字截斷或橫向溢出。

### UX-08：統一品牌及介面文字

**實際觀察**

網站使用 metaexb.com 網域，頁首顯示「MREI 元境智展」，客戶引言中出現「MetaExpo」。繁中介面的模板篩選另顯示「All」。

**修改要求**

- 確認主要對外品牌；在決定前，以現有頁首「MREI 元境智展」作為盤點基準，不自行更換品牌。
- 統一自有介面的品牌寫法及「建立／創建」、「發布／發佈」等用語。
- 「All」等介面文字納入既有繁中、簡中及英文翻譯。
- 客戶引言須先確認來源及引用授權；未經確認，不直接改寫他人的引言，也不假設引言真實或虛構。
- 網域與品牌名稱不同不必然需要改網域，可透過清楚的品牌說明處理。

**驗收標準**

- [ ] 自有介面的主要品牌用語一致。
- [ ] 三種語言下的主要操作沒有意外混語或原始翻譯鍵。
- [ ] 客戶引言及品牌歷史問題有明確處理記錄。

## 5. 建議實作位置

以下依專案既有結構列出候選位置；實作前應閱讀當前檔案，不代表每個檔案都需要修改。

| 範圍 | 候選位置 |
|---|---|
| 首頁、教學及主要入口 | `src/app/pages/Home.tsx` 與其引用元件 |
| 展覽列表空白狀態 | `src/app/pages/Exhibitions.tsx` |
| 模板及加入展廳 | `src/app/pages/VirtualGallery.tsx` 與其引用元件 |
| 展館參觀 | `src/app/pages/ExhibitionView.tsx`、`src/app/features/metaverse-studio/` |
| 登入及返回流程 | `src/app/pages/Login.tsx`、`src/app/pages/Register.tsx`、`src/app/auth.tsx` |
| 翻譯與品牌文字 | `src/app/i18n/catalogs/`、共用導覽及頁尾元件 |
| 新增公開入口與權限 | `src/app/routes.ts`、相關後端路由與服務 |

優先重用既有參觀流程及 UI 元件。示範展資料的保存方式應在實作時決定，避免為單一示範另建一套展館引擎。

## 7. 成效判斷

主要成功條件是：新訪客不需登入便能找到並完成一次示範參觀，而且能清楚知道如何開始建立自己的展覽。

若後續已有適當的分析與隱私機制，可比較首頁至示範展點擊、示範展至建展入口點擊，以及登入後回到建展流程的完成比例。先取得基線再設定改善目標，不以目前未量測的數據宣稱成效。
