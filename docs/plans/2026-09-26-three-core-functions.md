# MetaEXB 三個核心功能修改計劃

**Goal:** 僅以 3D 展覽、多人互動、Agent 三個主功能構成產品；教育、作品集和 CV 均為三者的使用情境，不新增第四個獨立產品模組。

**Architecture:** 沿用現有展場、展品、多人房間與 Agent。先收回獨立 CV 的主要入口，再把有價值的經歷與佐證內容放到具體展品及其導覽情境中。保留既有資料與相容路由，不能用刪除資料代替整合。

**Tech Stack:** 現有 React、React Three Fiber、Three.js、Zustand、Express、SQLite、Socket.IO；不增加框架。

**範圍來源：**2026-09-26 使用者明確要求。此文件取代 2026-09-25 計劃的產品定位及優先順序；舊文件的實測紀錄仍為歷史證據。英文為預設 UI；只在本機修改及驗收，不部署、不提交 Git。沿用使用者指定 GPT-6 Luna high 子代理協作，無須另選執行方式。

## 1. 三個主功能與修改方向

| 主功能 | 沿用優勢 | 修改重點 | CV 的位置 |
|---|---|---|---|
| 3D 展覽 | 編輯展場、擺放作品、公開參觀 | 展品能呈現作品背景、個人貢獻、過程和公開佐證；使用者在展場中查看與比較作品 | 個人作品展／經歷展的內容，不是獨立平面履歷產品 |
| 多人互動 | 同一房間、虛擬角色、即時交流與協作 | 圍繞同一件作品交流，清楚分辨參觀與編輯權限；先修復現有同步與重連，再考慮最小必要的共同關注提示 | 面試官、同學與作者一起參觀和討論作品，不新增招聘或班級系統 |
| Agent | AI 建展與展內對話／導覽 | 策展時使用作品資料，參觀時理解當前作品並引導查看佐證；資料不足時提問，不虛構能力 | 透過作品介紹經歷、回答有根據的問題，而不是只替履歷潤飾文字 |

主流程：**建立／整理 3D 展場 → 邀請他人共同參觀 → 在作品旁交流並向 Agent 提問。**

平面文字面板是展品的閱讀輔助，不得成為與展場分離的主流程。沒有作品或來源時，Agent 要明示資訊不足。公開展場和 Agent 不得自動取得 CV 私有來源。

## 2. 第一批：入口與定位修正

檔案：`src/app/pages/Home.tsx`、`src/app/components/Navigation.tsx`、`src/app/components/Footer.tsx`、相應三語 catalog、`config/homePrerender.ts`、`scripts/graduation-local-demo.mjs`。

1. 首頁主介紹回到 3D 展、多人、Agent；主要按鈕進入展覽與建展，不進入 `/cv`。
2. 移除主要導覽及頁尾獨立 CV 推薦入口；舊 URL 和資料暫保留相容，這不等於整合完成。
3. 本機預覽登入不再強制送往 CV；預覽橫幅也以 MetaEXB 命名。
4. 同步英／繁中／簡中文案與首頁預渲染。只描述現有功能，不能先宣稱作品佐證導覽等後續項目已完成。
5. 跑既有首頁、導覽、catalog／預渲染相關測試；在本機查看英文首頁。

## 3. 第二批：把內容整合進 3D 展品

先檢查：`src/app/pages/ExhibitionView.tsx`、`src/app/features/graduation/GraduationRoomSkills.tsx`、`src/app/features/cv/`、`src/app/modules/metaverse3d/store/`、`server/schemas/sceneSchema.js`。

1. 盤點現有展品欄位、CV 與展場連結，以及目前僅浮在展場上的履歷面板；避免再造另一套履歷模型。
2. 決定最小的「展品—公開經歷／來源」對應，復用已公開的內容；未對應資料不自動搬移或公開。
3. 在現有展品編輯／詳情中提供對應內容，觀眾選取展品即可讀取；舊來源可追溯。
4. 保存、重新載入、公開版本、取消公開皆需驗證。新增持久化欄位時同步前後端 schema，保留舊場景相容。
5. 驗收必須包含實際 3D 選取與讀取來源；只有平面頁顯示不算完成。

## 4. 第三批：修改現有 Agent 情境

先檢查：`src/app/modules/metaverse3d/agent/requestContext.ts`、`src/app/modules/metaverse3d/components/UI/AgentChatPanel.tsx`、`src/app/modules/metaverse3d/components/UI/useEditorAiBuilder.ts`、`server/services/agentService.js`、`server/services/exhibitionSceneContext.js`。

1. 查明當前作品／展區如何進入 Agent context；只附加第二批確認的授權公開資料，不另加獨立 CV 聊天頁。
2. Agent 說明作品與貢獻時引用具體公開來源；未提供來源、僅連結及自述須區分。
3. 沿用現有 AI 建展預覽及明確套用，不讓對話未經確認改寫作品。
4. 以公開／私有來源、缺證據、切換展品及未授權參觀者測試 context。模型回答品質與確定性整合測試分開記錄。

## 5. 第四批：多人參觀與三者連動驗收

先檢查：`server/multiplayer/socketServer.js`、`server/multiplayer/rooms.js`、現有 multiplayer store、`e2e/collaboration-recovery.spec.ts`、`e2e/editor-ai-builder.spec.ts`。

1. 用兩個獨立瀏覽器情境進同一展場，驗證同場存在、交流及既有權限。
2. 作者介紹一件作品，另一位觀眾可查看相同作品；Agent 回答必須來自正確展品資料。
3. 私人 Agent 對話不因同房而自動廣播；共享功能若確有需要再明確設計，不默認同步所有對話。
4. 驗證斷線重連、唯讀權限、保存及公開參觀。先處理已記錄的本機上傳／連線中斷，不用放寬測試掩蓋問題。

## 6. 不新增的主功能

不新增獨立 CV 中心、班級／教師審核平台、能力評分、招聘系統、社交動態、成長紀錄或競賽管理入口。既有歷史模組先退出產品主線；刪除路由或資料、遷移歷史內容要另列清單與相容處理，不能在入口調整中一併破壞。

## 7. 完成定義

使用者不用先填寫獨立履歷，也能建立作品展、邀請同伴參觀、與展內 Agent 互動。若使用 CV 情境，必須透過作品展、多人交流及作品脈絡下的 Agent 呈現價值。僅改介紹、隱藏連結或把 CV 浮在 3D 旁邊都不算整合完成。

本文件是修改計劃，不是完成報告。第一批的入口修正與第二至四批的實質功能整合須分開回報；不得把過往 graduation 流程測試當成新三核心流程的驗收。

## 9. 第二批實作範圍

本批直接擴充既有展品資料，不從 CV 私有資料自動搬移內容：`ExhibitItem.workContext` 為可選的貢獻、過程、成果、反思及最多五項來源。來源可提供名稱、HTTP(S) 網址及摘錄。作者在現有 3D 畫作檢查器編輯，參觀者在現有作品詳情閱讀；公開展覽會公開這些內容。

資料沿用場景保存、復原與多人場景同步；Agent 接收的是目前展品的欄位，不查詢私人 CV。作品詳情直接開啟原有 Agent 對話，需保留明確的作品焦點，並在切換場景或會話後清除。来源輸入先作草稿，合法後才送入共享場景，避免未輸入完整網址時破壞同步與自動儲存。

驗證範圍包括：舊場景相容、保存／載入／復原、來源欄位與協定校驗、多人送出與接收、詳情顯示、指定作品提問及 Agent 請求內容。模型提示要求區分作者自述、來源摘錄與未讀取的連結；提示存在不等於已證實模型回答正確，模型品質須另行評估。

本批實作與本機三核心連動已完成，詳見 [實作及驗收紀錄](../three-core-integration-validation.md)。既有 CV 資料未自動遷移；真實模型品質與此前完整 3D 回歸缺口仍未宣稱完成。
