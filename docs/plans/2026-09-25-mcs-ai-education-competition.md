## 1. 建議決策

建議選擇 **AI for Education**，暫定作品名稱 **MetaEXB Learn: Evidence-Based Reflection with AI**（MetaEXB Learn：以證據為本的 AI 反思學習）。

聚焦一個問題：中學生在整理專題、社團或服務學習經驗時，容易只列活動、欠缺個人貢獻與證據；生成式 AI 雖能潤飾文字，也可能把不完整紀錄寫成過度肯定的成就。教師則需要逐一核對來源與修改。

產品的核心流程是：**學生記錄真實經驗 → 提供獲准使用的證據 → AI 提問與提出有來源的草稿 → 學生核對、修正並說明理由 → 教師審核 → 2D／3D 成果展示。**

這個定位同時對應教育應用與 AI 素養。3D 是讓學生交流成果的展示層；研究重點是學生能否更清楚反思、辨識 AI 無根據的說法。建議以 SDG 4 優質教育作主要連結；只有取得低階裝置與不同使用者的實測證據後，才提出教育可及性的進一步主張。

不建議在交件前另造通用智能導師、自適應課程、模型訓練平台或大型虛擬校園。平台已有足夠功能，現在最需要的是收斂主題與取得可靠證據。

## 3. 專案現況：已有什麼，還缺什麼

以下依目前本機程式與文件判斷；程式存在不等於正式站已部署，也不等於教學效果成立。

| 能力 | 查閱到的證據 | 參賽處理 |
|---|---|---|
| 班級、邀請加入、投稿與審核 | `src/app/routes.ts`、`server/routes/graduationRoutes.js`、`docs/teaching-workflow.md` | 直接沿用師生流程 |
| 學習能力卡 | `src/app/features/graduation/SkillPortfolio.tsx`、`server/services/graduationSkillService.js` | 已有情境、角色、行動、成果、反思與來源，不重複開發 |
| 真實 AI 建議 | `suggestSkill` 使用 Qwen 相容 API，結構化輸出並保存 provider/model | 作主要 AI 展示；正式使用模型須以實際執行紀錄為準 |
| 人工判斷紀錄 | AI run、建議及 adopted／modified／rejected 決策已有持久化 | 補上「為何採納／拒絕」及學生核對證據的過程 |
| 教師與公開版本 | graduation 服務、公開頁、作品集與能力卡審閱元件 | 驗證私有來源不洩漏、修改後須重新審核 |
| AI 策展與成效填寫 | `graduationCurationService.js`、`CurationEvaluationPanel.tsx` | 可作輔助展示；現有自填時間差不能當作已證實效益 |
| AI 導覽與建展 Agent | `agentService.js`、`exhibitionBuilderAgentService.js` | 技術備答素材，避免搶走主線時間 |
| 2D 與 3D | `GraduationPublicPage.tsx`、`GraduationRoomSkills.tsx` | 2D 保持完整任務能力；3D 選用 |
| 英文 | 已有三語文案與英文 AI 能力卡輸出 | 仍須逐頁驗收英文錯誤訊息、示例、匯出及載入狀態 |

### 3.1 最重要的技術缺口

1. **來源 ID 合法不代表內容支持敘述。**目前 AI 結果會過濾不存在的 `evidenceIds`，但不會因此刪除或阻止原敘述。不可把通過 schema 與 ID 檢查稱為事實核實。
2. **連結不等於已讀取網頁。**能力卡把 URL 與文字送入模型，查閱的流程沒有取得網頁全文。需要標記「只有連結、尚未讀取內容」，或由學生加入經授權的短摘錄。
3. **提示詞限制不是安全保證。**要求不虛構已有實作，仍需要缺證據、矛盾資料、誘導指令等測試與人工檢查。
4. **公開權限與傳送 AI 的許可是兩回事。**目前 UI 提示 AI 會讀已保存來源，包括私人來源；建議增加逐項選擇送往供應商的控制，預設排除私人證據內容。
5. **已有決策類型，缺少可評估的判斷理由。**應記錄學生如何查證，而不是只增加採納率。

### 3.2 本機與正式站差異

`docs/plans/2026-09-23-student-skill-portfolio.md` 記載新增能力卡及歷史紀錄曾通過當時的檢查，但**沒有部署香港正式站**；原因是本機含大量其他變更，需要獨立候選版本與隔離驗收。9 月 23 日的教育入口計劃亦不能直接視為線上完成證據。

因此：不得直接在報告或影片中宣稱 `metaexb.com` 已具备所有本機功能。本輪没有驗證線上狀態；歷史測試數字亦不是本輪測試结果。較早的根目錄分析與補強計畫只作背景，已有的新功能以近期程式與紀錄為準。

## 4. 參賽版本範圍與使用流程

### 必須完成 P0

| 項目 | 修改方式 | 完成標準 |
|---|---|---|
| 教育情境 | 準備一班、一項專題與 3–6 張經授權或合成能力卡 | 新使用者能說明學習目標與下一步 |
| 證據狀態 | 區分學生自述、提供文字、僅有連結、來源不足；避免「已驗證」標籤 | 連結未讀、來源缺失都明確呈現 |
| AI 送出控制 | 預覽即將送出內容、選擇來源、過濾身份資訊 | 未選私人內容不在模型請求中；後端強制執行 |
| AI 決策理由 | 在現有採納／修改／拒絕旁新增理由及查證提示 | 理由與原 run、建議及版本關聯，僅學生與教師可見 |
| 英文完整路徑 | 參賽入口預設英文，準備英文資料與完整錯誤狀態 | 學生→AI→教師→公開頁→匯出全流程可用英文完成 |
| 實測與研究材料 | 先固定測試題、評分準則與紀錄格式，再收集結果 | 報告同時包含成功、失敗與限制 |
| 可展示候選版本 | 將所需本機功能整合到受控版本並驗收 | 線上示範與交件截圖指向同一已驗證版本 |

### 有餘力才做 P1

- 教師檢視「待补證據／待解釋決策」摘要；先做清單，不新增複雜分析儀表板。
- 匿名研究資料 CSV 匯出；若來不及，以人工去識別化研究表代替。
- 同一內容的 2D／3D 切換與低階手機觀察，改善已有流程，不新增場景引擎。

### 截止前不做

不訓練自有模型、不開放任意網址自動抓取、不建向量資料庫、不擴充多人伺服器架構、不新增職涯評分或自動認證。也不以自動套版／規則備援假扮 AI。

### 一個可實際演示的案例

學生提供「我協助同學整理調查資料」及一段工作紀錄。AI 應追問具體工作與結果，並只就已有內容提出草稿。若草稿把「協助」寫成「帶領團隊成功改善成績」，學生應拒絕或改回有證據的說法、記錄理由。教師檢查後批准公開卡片，觀眾看到的是經審核版本。

錯誤示例可作固定教學練習，但須標明「預設練習題」；現場 AI 建議則須真正呼叫模型。兩者不能混用來證明模型能力。

## 6. 研究與測試設計

### 研究問題

- RQ1：與一般文字模板相比，加入證據提示與 AI 反思建議，能否改善學生學習歷程的具體程度及證據一致性？
- RQ2：使用後，學生能否更準確辨識有根據與誇大的 AI 說法？
- RQ3：包含核對與修改的總時間是否可接受？教師是否減少追問？

### 建議小規模試點

招募目標為 8–12 名學生、1–2 名教師；這是規劃數量，尚未招募。由學校安排適當同意，使用匿名代碼，公開材料不顯示真實學生身份與私人原文。

採兩項難度相近的反思任務，分兩種次序：一半先用原有模板再用 AI 流程，另一半相反，減少熟悉度效應。兩條件使用相同時間上限、說明與材料類型。教師評分時隱藏工具條件，記錄是否仍可從文風猜到；不能宣稱完全雙盲。

樣本小，以個別配對變化、中位數、範圍及失敗原因為主，不宣稱因果關係或普遍學習提升。若無法招募學生，改用教師／同學模擬教育情境測試，清楚標記限制；不能以模擬結果冒充真實課堂成效。

### 指標與預先設定的判斷方式

| 指標 | 測法 | 建議判斷 |
|---|---|---|
| 反思品質 | 具體情境、個人貢獻、證據相符、反思深度各 0–3 分，共 12 分 | 報告配對分數；期待改善，不保證結果 |
| AI 素養 | 前後各 5 題等值情境題，辨識無證據／誇大／僅連結等問題 | 報告答對數及錯誤類型，避免用同題背答案 |
| 任務完成 | 能否完成卡片、決策、提交及審閱 | 小組整體目標 ≥80%，公布分子／分母 |
| 使用成本 | 計時包含閱讀、等待、核對、修改、錯誤重試 | 不只量模型生成時間；報告中位數和範圍 |
| 敘述可靠度 | 教師逐條判斷支持、部分支持、無支持 | 核心展示卡不得保留未標示的無支持事實 |
| 系統安全 | 越權、私有來源公開、未選內容外傳案例 | 固定測試集零洩漏；不推論為永遠安全 |
| AI 運行 | 成功／失败、模型、prompt 版本、延遲與可得用量 | 每次記錄；失敗不排除統計 |

AI 技術測試建議至少 20 題，分正常資料、缺漏、矛盾、只有連結、惡意指令五類；真實模型每題至少兩次。生成輸出必須人工核對語意；結構化格式通過率與事實支持率分開報告。

以匿名 participant ID、條件、任務、開始／結束時間、評分、錯誤、模型版本、run ID 記錄。研究公開資料只留必要衍生數值與授權片段；原始私人紀錄的保存期限、撤回與刪除負責人由學校在試點前確定。

## 9. 原創性、成本與主要風險

**原創性主張應有邊界：**擬議特色是把來源核對、AI 建議決策理由、教師審核與可分享成果連成教學流程。這不是「全球首創」判定。本次未完成外部競品實測；報告可由學生對普通作品集、一般聊天工具及本案使用同一任務做比較，只寫已觀察差異。

**成本：**延用現有基礎設施，不在交件前添購硬體或訓練模型。先跑 10 次代表性模型請求，從實際帳單／用量估算完整測試與演示預算；確認上限後再批量執行。設定請求長度、逾時與重試上限，避免以無限重試掩蓋失敗。

| 風險 | 應對與責任 |
|---|---|
| 學生資格／既有平台權利不明 | 學校先確認；貢獻與 AI 使用披露不可省略 |
| 只展示漂亮展場，教育價值不清 | 演示由學生反思問題開始，3D 只占一小段 |
| 模型虛構或引用不支持 | 來源狀態＋人工核對＋對抗案例，禁止自動認證 |
| 真人測試未能安排 | 提早招募；必要時誠實使用模擬教育測試 |
| 本機功能未上線 | 獨立候選、必要相依盤點、隔離驗收與部署紀錄 |
| 英文內容不完整 | 按端到端操作清單人工檢查，不只依靜態 i18n 報告 |
| 個資外傳或公开 | 後端限定 AI 輸入與公開欄位、最少保存、公開前審阅 |
| 時間不足 | 09-30／10-04 設範圍關卡，先刪 P1，保留交件時間 |

## 10. 完成定義與仍待確認事項

參賽版本完成須同時滿足：真實 AI 可運作；學生可說明輸入、模型、輸出與限制；證據不足不冒充認證；師生流程與英文展示通過；有誠實的教育測試結果；同意與素材來源可追溯；正式材料齊全且學校已核實提交。
