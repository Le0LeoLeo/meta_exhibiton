# Creation, sharing and measurement implementation plan

**Goal:** Provide upload → template → saved preview creation, public exhibition share metadata, and consent-based first-party funnel measurement.

**Architecture:** Extend the existing quick draft controller and deterministic layout styles with an explicit template gate. Serve escaped metadata in the real SPA HTML for public exhibition URLs. Record only allowlisted steps in short-lived, consented random sessions, aggregate ordered funnels through an operator-only report script, and expose withdrawal in the privacy page.

**Tech Stack:** React, TypeScript, Express, SQLite, Caddy, Vitest.

1. Extend `server/services/automaticExhibitionLayout.js`, `quickExhibitionService.js`, quick-exhibition types/controller and `QuickExhibitionCreate.tsx` with white, warm and dark templates. Preserve revision, candidate and publication protections. Test style round trips, explicit build gating and saved/dirty progress.
2. Add `server/routes/publicExhibitionPageRoutes.js`, copy the build shell into the app image and route exhibition pages through Express. Escape content, use canonical configured origin and only publicly bound media; never expose private data or bearer URLs. Test private/missing, malicious text, cover selection and fresh published/unpublished responses.
3. Add a minimal consent-aware client and settings panel, SQLite session-step repository and bounded ingestion endpoint. No identity, gallery IDs, content, URLs, IP or user-agent stored in this dataset. Expire after 30 days, respect browser opt-out signals, withdraw current session, and generate aggregate ordered visit/creation funnel reports through server-local operator access. Test consent, deduplication, ordering, retention and malformed requests.
4. Instrument real home, entry, artwork, guide and creation milestones. Run focused tests, server checks, types/lint and a fresh HK build. Verify desktop/mobile and consent behavior in the browser.
5. Validate a whitelisted release on isolated HK staging, including real upload/style/build/publish/share/unpublish and opt-in/withdraw. Deploy the existing app and web only after acceptance, preserve data/env/volumes and retain rollback. Verify public TLS, readiness, metadata, assets and ports; document results. No Git commits or push.
