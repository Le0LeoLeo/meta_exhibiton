# 自適應行動效能優化設計

日期：2026-06-16

## 目標

在不重寫既有 React Three Fiber 架構的前提下，同步改善全站前端與所有 3D 功能的手機體驗。一般規格的 iPhone Safari 與 Android Chrome 應以接近 60 FPS 為目標；複雜場景無法維持目標時，系統可自動降低畫質，優先確保操作持續可用、不長時間凍結且不因單一資源失敗而無法進場。

載入不設定固定秒數門檻。使用者應看到實際進度，並在核心場景可用時提早進入，其他內容於背景逐步補齊。

## 範圍

包含：

- 3D 觀展模式、3D 編輯器及其他使用共同場景基礎設施的功能。
- 全站主要路由的初始載入、圖片與影片資源策略、重複請求及非必要 React 重渲染。
- 手機觸控操作、頁面生命週期恢復、旋轉螢幕與作品詳情開關。
- 自動畫質判斷、即時 FPS 監測、漸進降級及保守恢復。
- iPhone Safari 與 Android Chrome 的 WebGL 穩定路徑。

不包含：

- 更換 Three.js、React Three Fiber、物理引擎或狀態管理方案。
- 為追求畫質導入 path tracing、體積光或其他高成本效果。
- 重做展覽內容、策展流程、多人協定或 AI 服務。
- 以 WebGPU 作為手機必要條件。

## 成功標準

- 一般手機在典型展館持續移動時以接近 60 FPS 為目標。
- 複雜展館即使降級，也能持續移動、觀看作品及開關詳情，不長時間凍結。
- 初次進場先提供可操作的基本空間，再補載高清素材、角色和附加服務。
- 自動畫質不因短暫掉幀頻繁升降；手動設定永遠優先於自動判斷。
- 單一模型、貼圖、影片縮圖、AI、語音、留言或多人連線失敗時，核心觀展仍可使用。
- 背景切回前景、旋轉螢幕及關閉作品詳情後，渲染與控制可正常恢復。

## 整體架構

保留現有 `performanceProfile.ts` 作為渲染設定的單一出口，在其前方加入自適應效能控制層。控制層只產生穩定、可測試的效能等級與運行訊號，不直接操作場景物件。

主要單元如下：

### 裝置能力評估

收集可安全取得的初始訊號：

- `navigator.deviceMemory`
- `navigator.hardwareConcurrency`
- 觸控與粗略指標媒體查詢
- viewport 尺寸與實際 pixel ratio
- `prefers-reduced-motion`
- Safari、iOS 與 Android Chrome 的能力差異

缺少瀏覽器資訊時採保守預設，不把缺值視為高階裝置。手機預設從 `performance` 或 `balanced` 啟動，不先以高畫質試跑。

### 即時效能監測

由 Canvas 內的輕量監測器收集 frame delta，使用滑動視窗計算 FPS 與長幀比例。監測器只定期提交彙總結果，禁止每幀寫入 React 或 Zustand state。

判斷原則：

- 持續低於下限才降級，短暫載入尖峰不觸發切換。
- 降級冷卻時間短，確保卡頓能快速改善。
- 升級需要更長的穩定期，且一次只提升一級。
- 頁面隱藏、載入中、詳情彈窗開啟或使用者停止互動時，不使用該段資料判斷升級。

### 畫質等級

延續三個有效等級：

- `quality`：桌面或明確有餘裕的裝置使用。
- `balanced`：降低 DPR、後製與額外光源，但保留主要陰影和多人內容。
- `performance`：手機 60 FPS 優先設定，關閉高成本效果並降低更新頻率。

既有 `low` 命名在實作時可保留作相容值，但 UI 與新邏輯以 `performance` 表達用途。資料遷移必須兼容已儲存的 `low` 設定。

### 手動覆寫

`auto` 模式允許自適應切換。使用者選擇固定等級後，控制器停止自動升降，但仍可在 WebGL context 失效等不可恢復情況採最低限度保護。手動選擇需持久化並在重新進場後保持。

## 降級順序

每次只跨一級，並依成本與視覺影響排序：

1. 限制最高 DPR，避免高解析手機造成過量像素填充。
2. 關閉 Bloom、Vignette 及其他全畫面後製。
3. 關閉額外投影燈、環境反射或次要陰影。
4. 降低陰影貼圖尺寸，必要時停用動態陰影。
5. 降低物理與多人位置同步的更新頻率。
6. 暫停或隱藏遠端角色、遠距高細節模型和非必要場景裝飾。
7. 在畫面靜止、頁面隱藏或詳情開啟時降低渲染頻率。

不以移除作品內容作為一般降級手段。作品可先使用縮圖或替代幾何，但其存在與可開啟性必須保留。

## 漸進載入

場景載入改為四個可觀察階段：

### 介面就緒

立即顯示展覽名稱、載入階段、進度、手機操作提示及返回入口。進度代表已完成的資源工作，不以假進度循環。

### 核心場景就緒

優先準備：

- 房間幾何與基本材質
- 玩家碰撞與初始位置
- 最低成本照明
- 作品位置、標題及低解析預覽
- 手機控制器

核心場景完成後允許進場，不等待高清作品、3D 模型、留言、AI、語音或多人連線。

### 附近內容補齊

依玩家位置與可見性排程資源：

- 鄰近作品高清內容優先。
- 視野外與遠距模型延後。
- 影片只載入 metadata 或縮圖，使用者開啟後才建立播放器。
- 多人、留言、AI 與語音在核心場景可操作後初始化。

### 閒置品質提升

只有在 FPS 持續穩定、網路未受限且使用者沒有密集操作時，才預取較高清素材或提升自動畫質。任何掉幀或頁面隱藏都可取消未必要工作。

## 手機互動

手機不依賴 Pointer Lock：

- 左側虛擬搖桿控制平面移動。
- 右側拖曳控制視角，限制俯仰角避免翻轉。
- 接近可互動作品時顯示大型按鈕。
- 互動按鈕需符合至少 44 CSS px 的觸控尺寸。
- 搖桿、視角與移動向量保存在 refs 或場景內部狀態，每幀合併處理。
- React state 只保存需要驅動 UI 的低頻事件，例如互動目標改變或操作模式切換。

桌面保留現有鍵盤與 Pointer Lock 行為。輸入適配器對 Player 提供共同的移動與觀看意圖，避免維護兩套碰撞和位移規則。

## 渲染生命週期

- `document.visibilityState === "hidden"` 時暫停非必要動畫、AI 距離檢查與多人視覺更新。
- 開啟作品詳情時停止玩家移動並降低場景更新頻率。
- 關閉詳情後，桌面恢復 Pointer Lock 必須由有效使用者手勢觸發；手機直接恢復觸控控制。
- viewport 或方向改變時更新 camera、DPR 上限與觸控區域，不重建整個場景。
- WebGL context lost 時顯示可理解的恢復介面；恢復失敗時提供重新載入場景選項。

## 全站前端效能

全站優化保持在現有架構內：

- 主要路由使用動態 import，首頁不載入 3D、圖表、管理端及其他大型功能。
- 大型頁面內再按功能切分，例如作品詳情、留言區、AI 面板與 3D 編輯器。
- 圖片指定合理尺寸、`loading="lazy"`、`decoding="async"` 與錯誤替代素材。
- 不可見影片使用 `preload="none"` 或 `preload="metadata"`，並在使用者開啟後才載入媒體。
- API 請求按展覽與作品識別去重；重複 render 不得重複匯入場景或取得相同資料。
- Zustand 使用細粒度 selector，避免大型物件訂閱驅動整個 UI 或 Canvas 外殼重渲染。
- 一般內容頁提供骨架或既有內容保留策略，避免路由切換白屏。
- 僅預取最可能的下一個路由或使用者附近內容，不進行全站無差別預載。

## 錯誤處理

錯誤以功能邊界隔離：

- 模型或貼圖失敗：顯示替代材質、縮圖或簡化幾何。
- 影片失敗：保留作品資訊與外部／下載入口。
- AI 或語音失敗：停用該次回覆，不影響移動和作品詳情。
- 多人連線失敗：退回單人觀展並顯示非阻塞提示。
- 留言失敗：只影響留言區，保留作品閱讀。
- 自動效能監測異常：回到初始裝置評估所得的固定等級。

錯誤提示不得覆蓋核心控制超過必要時間，也不能形成無法關閉的全螢幕阻塞。

## 狀態與資料流

1. 頁面建立時取得裝置訊號與使用者畫質偏好。
2. 控制器決定初始有效等級並建立渲染設定。
3. 漸進載入器發布載入階段與可進場狀態。
4. Canvas 啟動後，FPS 監測器定期回報彙總指標。
5. `auto` 模式根據門檻與冷卻時間變更有效等級。
6. 效能 profile 將等級轉換為 DPR、陰影、後製、燈光、物理及多人設定。
7. 使用者手動選擇後停止自動切換並持久化偏好。

裝置訊號、監測指標和載入狀態必須維持不同型別與責任，避免單一全域 store 同時承擔高頻資料與 UI 狀態。

## 測試策略

### 單元測試

- 初始裝置訊號到有效等級的映射。
- 缺少 `deviceMemory` 或 `hardwareConcurrency` 時的保守預設。
- 持續低 FPS 觸發逐級降級。
- 短暫掉幀不觸發切換。
- 穩定期不足不升級。
- 手動模式不接受自動升降。
- 已儲存 `low` 值可正確遷移。
- 載入階段在部分資源失敗時仍進入核心場景就緒。

### 元件與整合測試

- 手機控制器產生與桌面控制相同格式的移動意圖。
- 詳情開啟時停止移動，關閉後可恢復。
- 頁面隱藏時暫停監測與非必要更新。
- 單一資源、AI、多人成員或留言 API 失敗不阻塞場景。
- 路由重渲染不重複匯入同一展覽。
- 手動畫質選擇持久化並覆蓋自動結果。

### 真實裝置驗收

至少使用一台一般規格 iPhone Safari 與一台一般規格 Android Chrome：

- 冷啟動、再次進入與慢速網路進場。
- 典型展館持續步行、轉向及開關多件作品。
- 複雜展館掉幀後自動降級，且畫質不頻繁來回切換。
- 前景／背景切換、螢幕旋轉及來電式中斷後恢復。
- 影片、AI、語音、留言及多人功能逐一失敗時的局部降級。
- 長時間觀展時沒有持續增加的記憶體、材質或音訊資源。

效能紀錄至少包含平均 FPS、低百分位 FPS、長幀比例、有效 DPR、畫質等級與切換原因。開發診斷可顯示這些資訊，正式介面只呈現簡潔的畫質狀態。

## 實作邊界

- 優先擴充既有 `performanceProfile.ts`、`useScenePreloader.ts` 與 Canvas 組合層。
- Player 的碰撞與位移維持單一實作，手機只新增輸入適配。
- 高頻 FPS 與輸入資料不得每幀寫入 React state。
- 所有新增自動行為都必須可關閉、可測試並保留手動控制。
- 先建立量測與可觀察性，再根據資料調整門檻；不可只憑裝置名稱硬編碼畫質。
