# 上傳作品自動建展

第一期提供「選取圖片 → 自動保存私人展覽 → 預覽 → 發布」的完整入口。
建立過程採用固定排版規則，不需要設定 AI API key。

## 使用方式

1. 登入後，從首頁、虛擬展廳或「我的展覽」按「上傳作品建展」。直接入口為 `/virtual-gallery/quick-create`。
2. 選取或拖入 1–30 件靜態 JPG、PNG、WebP 圖片，每件最多 15 MB。展覽名稱可留空。
3. 圖片全部成功上傳後，自動安排白盒展廳、保存草稿並顯示預覽。作品依選取順序排列，圖片保持原比例。
4. 在 3D 預覽切換上一件／下一件作品，也可改用 2D 清單並點開圖片。暫時無法使用 3D 的裝置仍可預覽作品。
5. 按「發布展覽」後才公開，可複製分享連結或開啟公開展覽。

作品名稱預設取檔名，名稱及作者各最多 200 字元，作者及介紹未提供時留空。展覽名稱最多 120 字元。
目前支援繁體中文、簡體中文及英文。

## 修改及恢復

- 「管理作品」可修改展名、編輯每件作品的名稱、作者及簡介、補充或移除作品。作品名稱留空時使用檔名，作者可清空；簡介最多 5,000 字元，可留空或分段。按「保存並更新預覽」後，新名稱及作者會出現在作品標示牌及預覽中，在作品清單點開圖片亦可查看簡介。修改後產生新候選；選擇「套用此版本」保存至展覽，或「保留原版本」還原上一次保存的展名、作品清單及作品資料。
- 上傳期間可再選取一批圖片；排版及保存的短請求期間暫停清單操作。
- 部分檔案失敗時，其餘成功作品會保留。只需重試失敗項目；移除失敗項目後才會以其餘作品繼續。
- 草稿網址包含 `draftId`。重新整理後會讀取已保存作品及結果。瀏覽器無法恢復未上傳完成的本機檔案，畫面會標出需要重新選取的項目。
- 自動排展依實際牆厚及畫框背面定位，畫框和說明牌距牆約 2 mm。較早建立的私人草稿可從「管理作品」按「保存並更新預覽」，再「套用此版本」更新排版，無需重新上傳作品。
- 網路逾時後可重新載入草稿；重試建展使用原請求識別，避免重複保存。
- 版本衝突會停止舊提交，不覆蓋另一分頁或進階編輯器保存的結果。
- 進階編輯器第一次保存場景後，改由既有編輯流程管理及發布；舊快速草稿網址會引導回該展覽的進階編輯器。
- 作品從清單移除時不會直接刪除檔案，以免破壞仍被已保存版本使用的作品。

## 實作位置

| 功能 | 位置 |
| --- | --- |
| 頁面及主要操作 | `src/app/pages/QuickExhibitionCreate.tsx` |
| 上傳佇列、恢復、請求狀態 | `src/app/features/quick-exhibition/` |
| API client | `src/app/api/quickExhibition.ts` |
| 獨立的 3D 預覽 | `src/app/features/metaverse-studio/preview.ts`、`app/GalleryScenePreview.tsx` |
| 排版及完整性核對 | `server/services/automaticExhibitionLayout.js` |
| 草稿及生成服務 | `server/services/quickExhibitionService.js` |
| 路由及交易保存 | `server/routes/quickExhibitionRoutes.js`、`server/repositories/quickExhibitionRepository.js` |
| 圖片方向、尺寸及 metadata | `server/services/mediaMetadataService.js`、`mediaIngestService.js` |

啟動後端時會執行增量資料庫 migration，加入素材寬高及快速草稿表。
資料庫與上傳檔案沿用既有執行期儲存，不應提交 Git。

上傳限制預設為同一用戶每十分鐘 60 次，可容納兩批 30 件作品。
部署者仍可用 `RATE_LIMIT_UPLOAD_MAX`、`RATE_LIMIT_UPLOAD_WINDOW_MS` 調整；限制低於單批容量時，超出項目會顯示稍後重試提示，成功項目會保存。

預覽不匯入／保存全域編輯器場景，也不啟動多人編輯。正式場景只保存媒體 ID 及 `/api/media/<id>`；短效預覽憑證只加入顯示用副本。
快速發布會核對作品 ID、數量、來源、場景配置及最後保存版本；空展或未處理的候選不會發布。
