# AI Agent 主打功能需求

## 1. 產品定位

本專案的核心賣點是「空間感知 AI 展覽導覽員」，而不是單純的 3D 展覽平台或聊天機器人。

AI Agent 應能在 3D 展場中理解觀眾目前的位置、正在觀看的展品、停留時間、互動紀錄與偏好，並以不同導覽人格提供即時講解、主動推薦與連續式看展路線。

## 2. 目標使用者

- 一般觀眾：希望不用閱讀大量文字，也能理解作品重點。
- 學生創作者：希望自己的作品被更清楚介紹，並得到觀眾互動回饋。
- 教師 / 策展者：希望用 AI 導覽降低解說成本，讓線上展覽更像真實參觀體驗。
- 評審 / 管理者：希望快速看出展覽互動、導覽品質與觀眾偏好。

## 3. 核心使用情境

### 3.1 初次進入展場

觀眾進入 3D 展場後，可以選擇「自主參觀」或「AI 導覽」。若選擇 AI 導覽，Agent 會出現在場景中，說明自己的角色，並引導觀眾開始第一站。

### 3.2 靠近展品

當觀眾靠近某件展品時，Agent 應能辨識目前展品，並提供作品簡介、作者資訊、觀看角度或延伸問題。

### 3.3 主動問答

觀眾可以用聊天框詢問作品內容、創作意義、作者、推薦路線或比較不同作品。Agent 回答時必須使用目前展品與附近展品資料，不應捏造不存在的作者、日期或作品背景。

### 3.4 個人化推薦

Agent 應根據觀眾看過哪些作品、停留多久、是否互動、上一個推薦項目等資料，推薦下一件值得觀看的展品。

### 3.5 連續導覽

Agent 應能以「導覽路線」形式帶觀眾依序參觀多件作品，而不是只回答單次問題。

### 3.6 多人格導覽

觀眾可選擇不同導覽風格：

- 小白模式：簡單、親切、適合第一次看展。
- 專家模式：分析更完整，適合需要深入理解作品的人。
- 幽默模式：語氣輕鬆，但不能嘲笑作品、作者或觀眾。

## 4. 功能需求

### 4.1 Agent 參與模式

- 系統必須提供「自主參觀」與「AI 導覽」兩種模式。
- 選擇 AI 導覽後，Agent 必須顯示在 3D 展場中。
- Agent 必須能開啟或關閉聊天面板。
- Agent 必須能切換人格模式。

### 4.2 空間感知

- Agent 必須知道觀眾目前位置。
- Agent 必須判斷觀眾目前靠近哪一件展品。
- Agent 必須能跟隨觀眾移動。
- Agent 必須能在導覽模式中移動到目標展品附近。
- Agent 必須避免穿越牆面或離開展場範圍。

### 4.3 展品理解

- Agent 回答時必須帶入目前展品資料，包括標題、作者、描述、內容、類型與位置。
- Agent 可帶入附近展品資料，協助比較或推薦。
- 若展品資料不足，Agent 必須明確表示資訊不足，並改以可觀察元素引導觀眾。

### 4.4 對話能力

- Agent 必須支援使用者自由提問。
- Agent 必須保留最近對話脈絡。
- Agent 回答長度應能依人格調整。
- Agent 應支援繁體中文與英文回覆。
- Agent API 發生錯誤或缺少 API Key 時，必須提供可讀的 fallback 回覆。

### 4.5 訪客記憶

- 系統必須記錄觀眾已看過的展品。
- 系統必須記錄觀眾互動過的展品。
- 系統必須記錄觀眾在各展品的停留時間。
- 系統必須保存觀眾偏好的語言與人格。
- 訪客記憶應能跨 session 保存。

### 4.6 智慧推薦

- Agent 必須能推薦下一件展品。
- 推薦邏輯至少應考慮：
  - 未看過的展品優先。
  - 未互動的展品優先。
  - 與目前展品同類型的作品加權。
  - 停留時間較長的興趣訊號。
  - 避免連續推薦同一件作品。
- 推薦結果必須包含推薦原因。

### 4.7 語音導覽

- Agent 回答後應能播放語音。
- 語音 API 失敗時，不應阻塞文字回答。
- 語音導覽應尊重目前語言偏好。

### 4.8 導覽路線

- Agent 應能產生一條看展路線。
- 路線應根據展品位置與觀眾記憶排序。
- Agent 到達每一站後，應能提供該站導覽。
- 系統應顯示目前導覽進度，例如第 2 / 6 站。

### 4.9 Agent 狀態展示

- UI 應顯示 Agent 目前狀態，例如跟隨中、導覽中、回答中、推薦下一站。
- UI 應顯示目前 Agent 使用的是 Qwen 回答或 fallback 回答。
- UI 應顯示推薦展品與推薦原因。
- UI 應提供快速提問按鈕。

## 5. 非功能需求

### 5.1 回答品質

- Agent 不得捏造作品資訊。
- Agent 不得使用攻擊性、歧視性或嘲笑性的語氣。
- Agent 回答應像現場導覽員，不應過度像報告或條列筆記。
- Agent 回答應避免過長，除非使用者選擇專家模式或要求深入解釋。

### 5.2 效能

- Agent 移動與 3D 場景渲染不應造成明顯卡頓。
- Agent API 請求應有 timeout。
- Agent 回答等待期間應顯示 loading 狀態。
- TTS 播放不得阻塞聊天或場景操作。

### 5.3 可靠性

- AI API 無法使用時，系統仍必須可展示基本導覽能力。
- 訪客記憶保存失敗時，不應影響使用者繼續看展。
- Agent 行為狀態應避免卡在 answering 或 tour 狀態。

### 5.4 隱私

- 訪客記憶只應保存必要的互動資料。
- 不應將 JWT token、share token 或使用者敏感資訊暴露在 URL 或日誌中。
- 若未來加入公開部署，應提供資料清除或記憶重置機制。

## 6. 優先級

### P0：展示必備

- AI 導覽模式入口。
- Agent 3D 角色顯示。
- 靠近展品後可辨識目前展品。
- 基於展品資料回答問題。
- 三種人格切換。
- fallback 回答。
- 推薦下一件展品。
- 推薦原因顯示。

### P1：主打亮點

- 跨 session 訪客記憶。
- 根據停留時間與互動紀錄做個人化推薦。
- Agent 跟隨觀眾。
- 導覽路線模式。
- 語音導覽。
- 中英文切換。

### P2：進階加分

- Agent 主動開場與主動提醒。
- 導覽進度面板。
- 觀眾偏好分析摘要。
- 策展者查看觀眾常問問題與停留熱點。
- 多人展場中辨識不同觀眾的導覽上下文。

## 7. 驗收標準

### 7.1 基本問答

- Given 觀眾靠近一件有標題與描述的展品。
- When 觀眾詢問「請介紹這件作品」。
- Then Agent 必須回答該展品的標題與描述重點。
- And 不得捏造未提供的作者或日期。

### 7.2 人格切換

- Given 使用者選擇專家模式。
- When 使用者詢問作品意義。
- Then Agent 回答應比小白模式更深入，並提供觀看角度。

### 7.3 推薦邏輯

- Given 附近有兩件作品，其中一件已看過，另一件未看過。
- When Agent 產生推薦。
- Then Agent 應優先推薦未看過的作品。
- And 回傳推薦原因。

### 7.4 訪客記憶

- Given 使用者看過展品 A 並停留 30 秒。
- When 使用者重新進入同一展覽。
- Then Agent 應能讀取先前記憶。
- And 後續推薦應避免只重複推薦展品 A。

### 7.5 API fallback

- Given AI API Key 不存在或 API 請求失敗。
- When 使用者提出問題。
- Then Agent 必須回傳 fallback 回答。
- And UI 不應崩潰。

### 7.6 語音導覽

- Given Agent 已產生文字回答。
- When TTS API 可用。
- Then 系統應播放語音。
- When TTS API 失敗。
- Then 文字回答仍應保留。

## 8. 目前已具備的實作基礎

- Agent API：`POST /api/agent/reply`
- Agent 人格：小白、專家、幽默
- Agent 3D 行為：idle、follow、guide、tour、wander、answer
- Agent 對話面板
- 展品上下文序列化
- 附近展品列表
- 聊天歷史
- 訪客記憶 API
- 停留時間資料結構
- 推薦演算法
- Qwen / DashScope fallback
- TTS API

## 9. 目前建議補強

- 修正 Agent UI 與測試資料中的亂碼文字。
- 補上「開始 AI 導覽」的完整流程。
- 讓 tour 模式真正串接 AI 回答，而不是只有移動。
- 將推薦理由在 UI 中寫得更像人話。
- 補一個 Agent 狀態 / 記憶展示面板，讓評審快速看出 AI agent 的價值。
- 為 agent prompt、推薦邏輯、訪客記憶與 fallback 補更清楚的測試案例。
