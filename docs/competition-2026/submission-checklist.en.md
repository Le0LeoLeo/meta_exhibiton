# Submission checklist (English)

**Working checklist only. Nothing below is marked complete by this file.** Confirm the organizer's current requirements and deadline with the school before preparing final exports.

## Eligibility, authorship, and rights

- [ ] School confirms student eligibility, team composition, deadline, and application route.
- [ ] School confirms that extending and submitting the existing MetaEXB platform is permitted.
- [ ] Contributions separate existing platform work, student-authored work, teacher support, and AI-tool assistance.
- [ ] Code, text, images, music, recordings, and model/service use have documented rights and disclosures.
- [ ] Student names, likenesses, voices, and work have required permissions for the exact channels used.

## Product and evidence

- [ ] The exact candidate build, source revision, provider/model, and prompt version are recorded.
- [ ] English student-to-teacher flow is tested end to end, including empty, error, conflict, and unauthorized states.
- [ ] No live AI behavior is implied by static examples or replayed video.
- [ ] Claims are checked against reviewed sources; links are not described as read content.
- [ ] Private evidence and decision history do not appear in public output.
- [ ] Technical test inputs, failed runs, and actual outputs are retained in an access-controlled audit record.
- [ ] Any human study has school approval, consent/assent, withdrawal, retention, and deletion procedures before it starts.
- [ ] Results use observed denominators and include failures. Planned targets are not reported as results.

## English entry materials

- [ ] Project introduction completed from verified facts; expected outcomes are distinct from observed outcomes.
- [ ] Research report includes method, actual results or an explicit statement that no results are available, limitations, ethics, references, and disclosures.
- [ ] Poster uses only actual results; placeholders remain clearly marked until data exists.
- [ ] Demo video is within the current time/format limit and labels synthetic cases, static screens, and replays.
- [ ] English spelling, accessibility, captions, and student pronunciation/script have been reviewed by the team.
- [ ] Offline backup includes permitted video, screenshots, and presentation files; no claim of offline AI inference is made.

## File and upload checks

- [ ] Confirm current file names, dimensions, format, file-size limits, and number of uploads from the official current rules.
- [ ] Open every exported file on a second device and check links, fonts, image quality, captions, and page order.
- [ ] Remove credentials, private source text, personal data, internal notes, and unapproved media from export metadata and attachments.
- [ ] School submits the approved final version and saves the actual receipt/confirmation.
- [ ] Preserve a dated copy of submitted files and record the submission version.
