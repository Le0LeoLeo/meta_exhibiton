# Five-minute demo script (English, working outline)

**Status:** rehearsal outline. The current `/competition-demo` page is an orientation page with synthetic fixed examples; it does not call a live model. Do not read the “live AI” segment as if it has been performed. Record only from the exact candidate build that passed the team's checks.

| Time | Segment | Presenter action / spoken point | Evidence needed before recording |
|---|---|---|---|
| 0:00–0:30 | Learning problem | Explain why a reflection needs a clear personal contribution and evidence. | Teacher-confirmed context; no invented student story. |
| 0:30–1:10 | Learning record | Show the real tested card fields and clearly distinguish self-report from supplied source text. | Candidate build and synthetic or specifically authorized material. |
| 1:10–2:00 | Evidence check | Show a real permitted source-selection/status path; explain that a link alone is not read evidence. | Verify exact UI and backend behavior. If absent, disclose and show a static design proposal only. |
| 2:00–3:00 | AI suggestion, if implemented | Make a real bounded request with approved synthetic input. Name provider/model and show the actual unedited response and any error. | Record run ID, time, model, prompt version, result, and limitations. Never substitute the fixed practice draft. |
| 3:00–3:40 | Learner decision | Show a real accept/edit/reject choice and the student's own reason if this feature exists. | Feature and permission verified; do not fabricate a learner quote. |
| 3:40–4:15 | Teacher/public boundary | Show actual teacher review and approved public result; confirm private reasoning is not public. | Permission tests and exact candidate. Otherwise describe as planned. |
| 4:15–4:45 | Evaluation | Report actual tested cases and approved study observations, including failures and denominator. | Completed records only. If none, say evaluation is pending. |
| 4:45–5:00 | Limitations | State what the team did not verify and what students built themselves. | Contribution record and limitations checked by school. |

## Recording checks

- Capture the candidate URL/build ID, date, browser/device, and each real request's provider/model metadata.
- Use synthetic input unless specific school authorization permits another dataset; keep names and private evidence out of the recording.
- Show loading, error, retry, and permissions honestly. A successful response alone does not prove semantic accuracy.
- Label any static screen, fixed test, or recorded replay on screen and in narration. Never call a replay live inference.
- Keep a local copy of the final permitted video and supporting screenshots for offline presentation.
